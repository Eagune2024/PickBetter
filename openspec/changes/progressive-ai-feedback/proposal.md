# Proposal: 渐进式 AI 反馈体验优化

## Why

当前 AI DOM 修改功能在用户按 Enter 提交请求后，存在明显的体验问题：

1. **反馈延迟明显**：用户按 Enter 后要等待 100-500ms 才能看到 loading 状态
   - 元素信息提取是同步操作，会阻塞 UI 更新
   - 模糊指令的设计系统分析需要 100-150ms
   - 网络请求发送也需要时间

2. **缺乏进度感知**：用户只看到"AI正在思考..."的静态提示
   - 不知道系统在做什么
   - 不知道还需要等多久
   - 类似于"黑盒"体验，缺乏控制感

3. **与现代 AI 交互体验脱节**：用户期望类似 ChatGPT/Claude 的进度反馈
   - 这些工具会显示详细的步骤列表
   - 每个步骤完成后更新状态
   - 给用户清晰的进度感知

**为什么现在解决这个问题**：
- 刚刚实现了样式上下文感知功能，设计系统分析增加了延迟
- 用户开始频繁使用模糊指令，问题变得更加突出
- 这是影响用户体验的关键痛点

## What Changes

### 核心改进

**动态进度步骤列表**：
- 替换单一的"AI正在思考..."提示
- 根据任务类型动态生成步骤列表
- 实时更新每个步骤的状态（待处理 → 进行中 → 已完成）

**即时反馈机制**：
- 用户按 Enter 后立即显示步骤列表（<5ms）
- 使用微任务调度（`await Promise.resolve()`）让浏览器有机会更新 UI
- 在每个操作前后更新步骤状态

**细粒度步骤拆分**：
- 明确指令：提取元素信息 → AI 思考 → 应用修改
- 模糊指令：提取元素信息 → 提取父元素 → 分析兄弟元素 → 分析页面布局 → AI 思考 → 应用修改

### 技术实现

- 改造 `submitAiPrompt` 方法为异步函数
- 实现动态步骤生成逻辑（根据 `isFuzzyPrompt()` 结果）
- 实现微任务调度机制（使用 `await Promise.resolve()`）
- 新增 UI 组件：`showProgressSteps()` 和 `updateProgressSteps()`
- 新增辅助方法：`getStepIcon()`、`updateCurrentStep()` 等

### 非功能性改进

- 向后兼容：不改变现有的消息协议和数据结构
- 性能优化：微任务开销 <5ms，可忽略不计
- 错误处理：每个步骤失败时显示清晰的错误状态
- 防重复提交：添加 `isSubmitting` 标志防止快速连按

## Capabilities

### New Capabilities

- **progressive-step-feedback**: 渐进式步骤反馈能力，负责动态生成步骤列表、更新步骤状态、管理进度 UI

### Modified Capabilities

- **ai-dom-modification**: 现有的 AI DOM 修改能力，优化其提交流程和用户反馈机制

## Impact

### 影响的代码模块

- `source/ContentScript/elementPicker.ts`：
  - 改造 `submitAiPrompt` 方法为异步
  - 新增 `showProgressSteps` 方法
  - 新增 `updateProgressSteps` 方法
  - 新增 `getStepIcon` 方法
  - 新增 `updateCurrentStep` 方法（可选，用于细分进度）
  - 新增 `isSubmitting` 标志

- 无需修改 Background Script 或消息协议

### 用户体验变化

**修改前**：
```
用户按 Enter → [等待 100-500ms] → 显示 "AI正在思考..."
```

**修改后**：
```
用户按 Enter → [立即显示] → ○ 提取元素信息
                    → ⏳ 提取元素信息
                    → ✓ 提取元素信息
                    → ⏳ AI 正在思考...
                    → ✓ AI 正在思考...
                    → ✓ 应用修改
```

### 性能影响

- **响应时间**：Enter 到显示 UI 从 100-500ms 降至 <5ms
- **总体时间**：略微增加 5-10ms（微任务调度开销）
- **内存占用**：增加约 1KB（步骤列表数据）
- **DOM 操作**：增加约 12 次更新（可忽略）

## Acceptance Criteria

- [ ] 用户按 Enter 后立即看到步骤列表（<10ms）
- [ ] 明确指令显示 3 个步骤，模糊指令显示 6 个步骤
- [ ] 每个步骤完成后更新状态（✓ 或 ⏳）
- [ ] 进行中的步骤显示 spinner 动画和蓝色高亮
- [ ] 已完成的步骤显示绿色勾号并变淡
- [ ] 设计系统分析期间显示"正在分析配色..."等子进度
- [ ] 错误发生时显示失败的步骤和错误信息
- [ ] 快速连按 Enter 时不会重复提交
