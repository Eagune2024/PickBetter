# Proposal: 样式上下文感知的 AI DOM 修改功能

## Why

当前的 AI DOM 修改功能在用户给出明确的修改指令时工作良好（如"把背景改成红色"），但当用户使用模糊的描述性语言时（如"让这个按钮更现代"、"优化一下样式"），AI 模型只能看到目标元素自身的有限样式信息，无法理解页面的整体设计风格、配色方案、字体系统等上下文，导致生成的修改往往与页面风格不协调。

随着 AI DOM 修改功能的逐步完善，用户开始尝试更自然的交互方式，模糊指令的使用频率增加。现在是提升 AI 对页面设计理解能力的最佳时机。

## What Changes

### 新增功能

- **样式信息扩展**：将提取的 CSS 属性从当前的 11 个扩展到 50+ 个，覆盖颜色、排版、布局、视觉效果、交互状态等完整维度

- **层级上下文分析**：
  - 提取父元素的样式信息
  - 查找并提取相似兄弟元素的样式
  - 计算元素间的样式相似度

- **页面设计系统智能推断**：
  - 自动分析页面配色方案（主色调、背景色、文本色、边框色）
  - 识别字体系统（字体家族、字号规模、字重、行高）
  - 推断间距系统（常用间距值、基础间距单位）
  - 提取圆角系统（常用圆角值）
  - 分析阴影系统（常用阴影模式）

- **智能触发机制**：
  - 实现模糊度检测算法，判断用户指令是否明确
  - 明确指令（如"改颜色"）：只使用基础样式信息，保持高性能
  - 模糊指令（如"更现代"）：自动触发深度分析，提供完整上下文

- **增强的 AI Prompt**：
  - 根据上下文信息动态构建 prompt
  - 包含页面设计系统摘要，帮助 AI 理解整体风格
  - 包含相似元素参考，支持"和那个一样"的指令

### 技术实现

- 新增 `StyleAnalyzer` 工具类，负责页面设计系统分析
- 扩展 `ElementInfo` 类型定义，添加可选的上下文字段
- 优化 `extractElementInfo` 方法，支持按需提取不同层级的上下文
- 扩展 `buildPrompt` 方法，智能格式化上下文信息

## Capabilities

### New Capabilities

- **style-context-extraction**: 样式上下文提取能力，负责从页面中提取元素样式、层级关系和设计系统信息

- **fuzzy-prompt-detection**: 模糊指令检测能力，负责判断用户指令是否需要深度样式分析

- **design-system-inference**: 设计系统推断能力，负责自动分析并总结页面的设计模式

### Modified Capabilities

- **ai-dom-modification**: 现有的 AI DOM 修改能力，增强其样式信息获取和 prompt 构建逻辑

## Impact

### 影响的代码模块

- `source/types/operations.ts`: 扩展 `ElementInfo` 接口，添加上下文字段
- `source/ContentScript/elementPicker.ts`:
  - 优化 `extractElementInfo` 方法
  - 新增 `isFuzzyPrompt` 方法
  - 更新 `submitAiPrompt` 方法，支持智能触发
  - 新增样式相似度计算方法
- `source/utils/aiClient.ts`: 优化 `buildPrompt` 方法，利用上下文信息
- `source/utils/styleAnalyzer.ts`: **新增**，实现页面设计系统分析

### API 变更

- `ElementInfo` 接口添加可选字段（向后兼容）
- 无破坏性变更

### 依赖项

- 无新增外部依赖
- 使用现有浏览器 API（`getComputedStyle`, `querySelectorAll`）

### 性能影响

- 明确指令：无性能变化
- 模糊指令：额外 100-150ms 分析时间（可接受）
- 可选优化：实现设计系统缓存，同一页面只分析一次

### 用户体验

- 明确指令：响应时间不变（~2-5s AI 响应）
- 模糊指令：响应时间略增（~2-6.5s，含分析时间），但结果质量显著提升
- 更自然的交互方式，用户无需了解技术细节即可表达设计意图
