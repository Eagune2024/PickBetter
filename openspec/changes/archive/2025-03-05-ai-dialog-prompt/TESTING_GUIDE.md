# AI 对话框功能 - 测试指南

本指南提供详细的测试步骤，用于验证 `ai-dialog-prompt` 变更的完整功能。

## 测试前准备

1. **构建扩展：**
   ```bash
   npm run build
   ```

2. **加载扩展到浏览器：**
   - Chrome/Edge: 打开 `chrome://extensions/`，启用"开发者模式"，点击"加载已解压的扩展程序"
   - Firefox: 打开 `about:debugging#/runtime/this-firefox`，点击"临时载入附加组件"

3. **准备测试页面：**
   - 可以使用任何网站进行测试
   - 建议测试多种类型的网站（GitHub、Twitter、电商网站等）

---

## 测试任务 6.1：状态转换测试

**目标：** 验证所有状态转换正确工作

### 测试步骤

1. **IDLE → PICKING**
   - 打开扩展 popup，点击"开始选择"
   - 验证：`[ElementPicker] 选择模式已启动,按ESC退出` 消息出现在 console

2. **PICKING → SELECTED**
   - 在 PICKING 状态下，点击页面上的任意元素
   - 验证：
     - 元素被高亮（蓝色边框）
     - AI 对话框出现
     - Console 显示选中元素信息
     - 输入框自动获得焦点

3. **SELECTED → PICKING (Enter 提交)**
   - 在对话框中输入任意文本（如"把按钮改成红色"）
   - 按 Enter 键
   - 验证：
     - Console 显示 `[ElementPicker] AI Prompt: ...`
     - 对话框消失
     - 返回 PICKING 状态（可继续选择其他元素）

4. **SELECTED → PICKING (ESC 取消)**
   - 点击元素进入 SELECTED 状态
   - 按 ESC 键
   - 验证：
     - 对话框消失
     - 返回 PICKING 状态

5. **PICKING → IDLE**
   - 在 PICKING 状态下，按 ESC 键
   - 验证：
     - `[ElementPicker] 选择模式已退出` 消息
     - 所有覆盖层消失

### 测试结果

- [ ] 所有状态转换正常
- [ ] Console 输出正确

---

## 测试任务 6.2：对话框定位测试

**目标：** 验证对话框在各种位置下都能正确显示

### 测试步骤

1. **屏幕四角测试**
   - 找到页面左上角的元素并选中
   - 验证：对话框显示在合适位置（不被截断）
   - 重复测试右上、左下、右下角元素

2. **屏幕中央小元素**
   - 找到页面中央的一个小按钮或链接
   - 验证：对话框显示在元素外部（右侧或左侧）

3. **屏幕中央大元素**
   - 找到占据大部分视口的大元素（如 hero section）
   - 验证：对话框显示在元素内部左上角

4. **边缘情况**
   - 选中靠近屏幕边缘的元素
   - 验证：对话框自动调整位置，不超出视口

### 测试结果

- [ ] 四角元素定位正确
- [ ] 中央小元素定位正确
- [ ] 大元素定位正确（内部）
- [ ] 边缘元素定位正确

---

## 测试任务 6.3：事件隔离测试

**目标：** 确保 SELECTED 状态下对话框可正常交互，不影响选择器

### 测试步骤

1. **对话框悬浮测试**
   - 进入 SELECTED 状态
   - 鼠标悬浮在对话框标题、输入框、提示文字上
   - 验证：不触发页面其他元素的高亮

2. **对话框点击测试**
   - 在对话框内点击（标题、输入框、提示区域）
   - 验证：不触发选择器的点击处理

3. **对话框输入测试**
   - 在输入框中输入文字
   - 验证：可以正常输入，不触发其他事件

4. **其他元素悬浮测试**
   - 在 SELECTED 状态下，鼠标悬浮页面其他元素
   - 验证：其他元素不高亮

5. **其他元素点击测试**
   - 在 SELECTED 状态下，点击页面其他元素
   - 验证：不触发选择，对话框保持显示

### 测试结果

- [ ] 对话框悬浮不触发高亮
- [ ] 对话框点击不触发选择
- [ ] 输入框可正常交互
- [ ] 其他元素不高亮
- [ ] 其他元素不被选中

---

## 测试任务 6.4：快捷键测试

**目标：** 验证所有快捷键正确响应

### 测试步骤

1. **PICKING 状态 ESC**
   - 启动选择器
   - 按 ESC
   - 验证：退出选择器模式

2. **SELECTED 状态 Enter (提交)**
   - 选中元素
   - 在输入框输入"test prompt"
   - 按 Enter
   - 验证：
     - Console 输出 prompt
     - 对话框关闭
     - 返回 PICKING 状态

3. **SELECTED 状态 ESC (取消)**
   - 选中元素
   - 按 ESC
   - 验证：
     - 对话框关闭
     - 输入框内容被丢弃
     - 返回 PICKING 状态

4. **空输入 Enter**
   - 选中元素
   - 不输入任何内容（或输入后删除）
   - 按 Enter
   - 验证：正常处理，输出空字符串

5. **滚动阻止**
   - 在 PICKING 或 SELECTED 状态
   - 尝试使用方向键、PageUp/Down、空格键滚动
   - 验证：页面不滚动

### 测试结果

- [ ] PICKING 状态 ESC 退出
- [ ] SELECTED 状态 Enter 提交
- [ ] SELECTED 状态 ESC 取消
- [ ] 空输入正常处理
- [ ] 滚动快捷键被阻止

## 测试任务 6.5：跨浏览器测试

**目标：** 确保功能在不同浏览器中一致

### 测试步骤

1. **Chrome 测试**
   - 在 Chrome 中完成上述所有测试
   - 验证：所有功能正常

2. **Firefox 测试**
   - 在 Firefox 中完成上述所有测试
   - 验证：所有功能正常

3. **对比检查**
   - 对比两个浏览器中的：
     - 对话框样式（字体、颜色、间距）
     - z-index 层级（对话框始终在最上层）
     - 事件处理行为
     - 快捷键响应

### 测试结果

- [ ] Chrome 功能正常
- [ ] Firefox 功能正常
- [ ] 两浏览器行为一致
- [ ] 样式表现一致

## 测试任务 6.6：主流网站兼容性测试

**目标：** 确保对话框在各种网站环境下正常工作

### 测试步骤

1. **GitHub 测试**
   - 访问 https://github.com
   - 测试选中各种元素（按钮、导航、链接）
   - 验证：对话框显示正确，不被页面样式覆盖

2. **Twitter/X 测试**
   - 访问 https://twitter.com
   - 测试选中推文、按钮、链接
   - 验证：对话框显示正确，交互正常

3. **电商网站测试**
   - 访问淘宝、京东或其他电商网站
   - 测试选中商品卡片、按钮、图片
   - 验证：对话框显示正确

4. **复杂网站测试**
   - 访问使用复杂 CSS 框架的网站（如 Ant Design、Material UI 网站）
   - 验证：对话框样式不受影响

### 检查项

- [ ] GitHub 兼容
- [ ] Twitter 兼容
- [ ] 电商网站兼容
- [ ] 复杂网站兼容
- [ ] z-index 始终最高
- [ ] 对话框可交互
